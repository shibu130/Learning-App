📚 Kannada Learning App — Knowledge Graph

Complete Architecture, File Structure & API Documentation

1. Project Overview

Kannada Learning App is a modern, responsive web application for learning the Kannada writing system. Built with SvelteKit 5 + Bootstrap 5, it consumes local JSON datasets and uses the browser's Web Speech API for pronunciation.

Core Principle: Data-driven architecture — all learning content lives in /static/kannada-dataset/ as JSON. The UI never hardcodes Kannada characters, words, or categories.

3. Phase 1 — Dataset Files

Five JSON files form the single source of truth. Every entry is self-contained.

3.1 vowels.json 16 items

Independent vowels (ಸ್ವರಗಳು): ಅ, ಆ, ಇ, ಈ, ಉ, ಊ, ಋ, ೠ, ಎ, ಏ, ಐ, ಒ, ಓ, ಔ, ಅಂ, ಅಃ.

FieldTypeDescription
idnumberUnique identifier (1–16)
typestringAlways "letter"
categorystring"vowel"
letterstringKannada character
romanstringRoman transliteration
meaningstringEnglish label
ttsstringText sent to speech engine

3.2 consonants.json 36 items

Consonants (ವ್ಯಂಜನಗಳು): ಕ through ಜ್ಞ including all five vargas and miscellaneous.

Every consonant × 15 vowel signs = 540 combinations (ಗುಣಿತಾಕ್ಷರ).

Common conjunct letters (ಒತ್ತಕ್ಷರ): ಕ್ಕ, ಕ್ತ, ಕ್ನ, ಗ್ನ, ಶ್ರ, ಕ್ಷ, ಜ್ಞ, etc.

4. Services Layer

4.1 datasetService.js JavaScript

Central data layer — all components import from this service, never from JSON directly.

FunctionReturnsDescription
getVowels()ArrayAll items with category: "vowel"
getConsonants()ArrayAll items with category: "consonant"
getVowelCombinations()ArrayAll items with category: "vowel_combination"
getConjuncts()ArrayAll items with category: "conjunct"
getNumbers()ArrayAll numeral items
getAllLetters()Array[Object]5 sections merged: [{section, title, data}]
search(query)ArrayFuzzy match across letter/roman/meaning/word fields
clearCache()voidReset in-memory cache for fresh fetches
🚀 Architecture: Uses a simple in-memory cache (object cache = {}). First call fetches via fetch() from /kannada-dataset/{filename}; subsequent calls return cached data.

4.2 speechService.js JavaScript

Abstraction over the browser's Web Speech API. Swap-friendly for future audio file playback.

FunctionReturnsDescription
speak(text)Promise<void>Speaks Kannada text. Cancels previous utterance. Lang=kn-IN, rate=0.85
stop()voidImmediately cancels any ongoing speech
isSpeechSupported()booleanChecks if speechSynthesis exists in window
💡 Design Rationale: All UI components call speak(). If you later replace with pre-recorded audio, only the internals of speechService.js change — no UI changes needed.

5. UI Components

5.1 AlphabetCard.svelte Svelte

Reusable card displaying a Kannada letter with roman transliteration and an audio button.

Props: letter, roman, tts, selected, onSelect
Behaviour: Click plays tts via imported AudioButton, toggles .selected / .playing CSS classes for visual feedback. Animated card-pop on click.

5.2 AudioButton.svelte Svelte

Small circular button (36×36px) with volume icon. Calls speechService.speak(text).

Props: text — the Kannada string to pronounce
States: playing (disables button, shows filled icon), idle (shows outline icon).

5.3 SearchBar.svelte Svelte

Full-width search input with icon, clear button, and real-time results callback.

Props: onResults(results) — callback fired on every keystroke
Behaviour: Debounce-free for simplicity. Clears results when input is empty. Shows spinner during async search.

5.4 PageHeader.svelte Svelte

Page-level heading with optional subtitle and icon. Used by home, alphabet, and settings pages.

Props: title, subtitle, icon (Bootstrap icon class)

5.5 SectionHeader.svelte Svelte

Section divider heading with underlines and optional icon. Marks each alphabet category.

Props: title, icon

6. Routes & Pages

6.1 +layout.svelte Root Layout

Wraps all pages. Provides:

  • Navbar — purple gradient bar with links to Home, Alphabet, Settings
  • Main container — Bootstrap .container with padding
  • Footer — centered copyright text
  • Head — loads Bootstrap 5 CSS and Bootstrap Icons from CDN

6.2 +layout.js Config

export const prerender = true;
export const ssr = false;
export const trailingSlash = 'always';

Enables static site generation (prerender all pages at build time). SSR disabled since datasets are fetched client-side via fetch().

6.3 +page.svelte Home

Landing page with:

  • 3 gradient cards (Alphabet → links to /alphabet, Practice → placeholder, Settings → links to /settings)
  • About card — explains the data-driven design

6.4 alphabet/+page.svelte Alphabet

The core learning page. Flow:

  1. onMount → calls getAllLetters() → fetches all 5 datasets
  2. Renders SearchBar on top → typed query triggers search() → displays results inline
  3. Below search, renders 5 sections (Vowels, Consonants, Vowel Combos, Conjuncts, Numbers) each with a SectionHeader
  4. Each section maps over data items → renders responsive grid (col-6 col-md-4 col-lg-2) of AlphabetCard components
  5. Clicking a card triggers speak(tts) and sets selectedId for visual highlight

6.5 settings/+page.svelte Settings

Three settings panels:

  • Speech Settings — rate slider (0.5–2.0), pitch slider, test button, TTS availability badge
  • Data Management — "Clear Cache & Reload" button
  • About — version info, dataset stats, coming-soon roadmap
  • Quick Tips — sidebar card with usage tips

7. Data Flow Diagram

  [JSON files]
  /static/kannada-dataset/
      │
      ▼
  datasetService.js         ← only file that knows about JSON paths
      │
      ├── getVowels()
      ├── getConsonants()
      ├── getVowelCombinations()
      ├── getConjuncts()
      ├── getNumbers()
      └── getAllLetters()    ← merges all 5 datasets into sections
           │
           ▼
  alphabet/+page.svelte     ← calls on mount, loops sections
      │
      ├── SectionHeader     ← section title
      ├── SearchBar         ← calls datasetService.search()
      └── AlphabetCard × N  ← receives letter/roman/tts via props
           │
           ├── AudioButton  ← calls speechService.speak(tts)
           └── CSS classes  ← :hover, :active, .selected, .playing
Key Data Flow Principles:
1. JSON files → datasetService → Svelte components
2. Components never import JSON directly
3. All datasets retrieved via fetch() at runtime (client-side)
4. Future dataset addition = add JSON file + extend datasetService + optionally create new route

8. Future Extensibility Guide

To add a new module (e.g., Vocabulary), follow this checklist:

Step-by-step:

  1. Create JSON file static/kannada-dataset/vocabulary.json
  2. Extend datasetService — add getVocabulary() function following existing pattern
  3. Optionally update getAllLetters() or create a new page
  4. Create route page src/routes/vocabulary/+page.svelte
  5. Add link in navbar layout

Planned future datasets:
